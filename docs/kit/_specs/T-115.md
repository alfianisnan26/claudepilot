# T-115 Elevate the Portal MCP: the operating environment for every agent (charter, decisions, standards, playbooks, reviews)

Owner (2026-10-13): 'MCP must be elevated, so that context like this (the charter, the standards, the decisions, the playbooks, the scoring) is DELEGATED to every existing and every new agent, so that pilot is always a consistent and effective environment for autonomous work.' Today the Portal MCP gives an agent tools only: apps/server/src/portalmcp/server.ts #instructions is four generic lines (max 2,048 characters), and resources and prompts (resources.ts) exist ONLY for an admin's token ('Agents' tokens get none of this: tools only'). So a new agent learns nothing of the charter, the standing decisions, the standards or the playbooks unless a brief happens to say so, and the decisions the owner makes live in ticket comments where agents contradict them (the coordinator found five contradictions by hand today). Build the MCP as the one channel through which the operating environment reaches EVERY agent, in any workspace and any program (ClaudePilot, Konfersi), started by the UI, a ticket, a trigger, session_spawn or an external client:

1. SERVER INSTRUCTIONS, personalised and short (raise INSTRUCTIONS_MAX to 4 KB, still static text built by the portal, never workspace text): what pilot is; the charter's zero-tolerance list and duties in six lines; 'call session_context first and at every resume'; who the agent is (workspace, program, role if known, session, ticket); the charter version hash; where the rest is (resources and tools). Same text for an external client (the owner's Claude) minus the agent lines.
2. RESOURCES AND PROMPTS FOR AGENTS TOO (the same read-only views, the same scope checks and redaction as the tools behind them): `pilot://charter`, `pilot://standards` (the standards check's list, per program), `pilot://decisions` and `pilot://decisions/{id}`, `pilot://playbooks/{task type}` (T-114), `pilot://me` (my scorecard, my open peer reviews, my gaps), `pilot://program/{name}` (the program's rules: Konfersi's RULES and briefs). PROMPTS (slash-command style, usable by the agent and the owner): `start-unit` (name the task type and size, read decisions and playbooks, write the decision record, plan), `report` (failures first, evidence links, not-verified stated), `escalate` (is it REQUIRED? if not, decide by the default and write it), `review` (the peer-review rubric), `reflect` (the post-unit reflection).
3. A TOOL `session_context` (read): the personalised brief for THIS session, versioned: standing decisions that apply (workspace, program, task type), the charter version, open incidents that touch it, the checks it must pass, the assigned ticket and its buckets, my efficiency terms, the playbooks adopted for the type. The result carries `charter_version` and `decisions_version`; every other tool result carries a one-line notice when either changed since the session last read them ('charter changed: call session_context'), and the portal records in the audit which versions each session ran with.
4. A DECISIONS REGISTRY as a first-class object (the answer to 'agents contradict the owner's decisions'): id (D-n), statement, scope (global, program, workspace, area), date, who decided (the owner, or an agent under a default), reason, supersedes and superseded-by, status (standing, retired), links (tickets, PRD sections). Tools `decision_search`, `decision_get`, `decision_record` (an agent records a decision it takes under a default: options, default, reason, BEFORE acting; a decision of the owner is recorded by the owner or the coordinator from a ticket comment with one tool call). Recording CHECKS for contradictions with standing decisions (a rule first, text similarity second, never silent): a conflict returns the conflicting decision and asks the agent to either follow it or open a ticket 'decision conflict' for the owner. Import the decisions the owner made on 2026-10-13 as the first entries (uat later, one pod, no GitHub Actions for stg, deploy approval by rule, heavy jobs through job-run, Konfersi stg only, charter, secrets only via pools, and the others on the tickets T-33, T-42, T-93, T-94, T-96, T-103, T-108, T-110).
5. DELIVERY GUARANTEE for every session, existing and new: (a) the pilot MCP is always present (per-session token) and a session that started without it, or whose tool list changed, shows the 'Tools changed' chip and restarts at the next turn end when autonomous (T-102); (b) the Context pool carries the charter essentials and the program overlay as a MANAGED default context assigned to every workspace (editable by the owner only, versioned, delivered like any context); (c) the Skillset pool carries the default skills `charter`, `knowledge` (T-106), `efficiency` and `peer-review` for every workspace; (d) precedence is written once: charter, then standing decisions, then program rules, then the role's brief, then the ticket; (e) a session whose charter version is older than the current one gets the chip and, if autonomous, restarts at the next turn end (never mid-turn); (f) a NEW workspace or program inherits all of it with no setup (the defaults live in the platform settings).
6. SAFETY: all text served is built by the portal from stored, owner-edited or portal-written sources; agent-written text (a decision an agent recorded, a playbook proposal) is labelled `untrusted_text` with its source until a person or the adoption test adopts it; no secret ever; size caps; the same sanitizer; an agent can read the charter but never change it, nor a decision of the owner, nor the scoring (the charter's walls); `decision_record` by an agent is rate limited and audited.
7. TESTS: instructions per principal (agent, admin, external), the resources for an agent token with the scope checks, the prompts, `session_context` content and versioning, the change notice on another tool's result, the contradiction check (a rule hit, a near-duplicate, a clean record), the default Context and skills on a NEW workspace and on a program overlay, a session on an old charter version, the audit of versions per session, redaction and caps. PRD: portal-mcp.md gets a section 'Operating environment'; the charter file stays the source of the text and the portal reads it from a versioned store, not from the repo at runtime.
8. ROLLOUT: first the decisions registry and `session_context` (they stop the contradictions), then instructions and the default Context, then resources and prompts for agents, then the version notices and the restart rule. The Konfersi orchestrator adopts the charter into docs/agentic/RULES.md by a PR on its side the same day.
Priority high, wave 1-2, rank-04d (right after T-108's first slices): it is what makes every other ticket reach every agent.
