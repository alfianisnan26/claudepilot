# T-108 Full autonomy: close every dependency on a person, the coordinator chat or one pod process

Owner (2026-10-13): 'make sure 100% fully autonomous.' This is the umbrella: every place where the setup still depends on a person, on the coordinator's own chat, or on one process in the pod, with its fix, who decides, and the order. Each line is a slice or a decision; tick them here.

DEPENDS ON THE COORDINATOR'S CHAT (it ends when that chat ends or hits its own limit):
1. The hourly health sweep, the deploy approvals, the quota moves, restarting chats, reassigning tickets: today a Claude chat of the coordinator does them (cron inside it). FIX: a built-in WATCHDOG in the portal, not an LLM: an hourly (and on-event) deterministic sweep run by the triggers machinery: chats alive and in the right mode, supervisor/Keep going state, quota (move at 10%), CI runs failed or stuck > N minutes, orphan Jobs, pod load/memory/disk-free, delivery synced, tickets assigned to ended sessions (reassign), a chat idle with work left. It repairs what it safely can (wake, continue, move, reassign, cancel an orphan Job) and writes every action to the audit/trail; it opens a ticket for anything it cannot repair (title, evidence, tag `watchdog`) and sends ONE push 'Needs you' only for a real incident. Slice of T-104 (Keep going); the Home page gets an 'Autonomy' widget (chats, quota, last deploy, open incidents, items waiting for a person). T-104 owns the policy and the lease; this adds the sweep.
2. A pod restart kills every chat, the supervisor and the CI runner. FIX: T-104 (the loop is in the portal and restarts chats by itself) + T-99 (runner reinstalled at once).

DEPENDS ON A PERSON (decision the owner must make; the recommendation is first):
3. DEPLOY APPROVAL of ClaudePilot's own deploys (PRD FR41: a person only, no tool, never an agent). Today the coordinator chat approves as the owner's delegate. For full autonomy the PORTAL (not an agent) may approve by RULE: an environment option 'auto-approve when: the full gate is green on this exact commit, verify and rollback exist, no migration or authz change in the diff unless flagged, within an allowed time window, at most N per day', off by default, turned on by the owner, audited, with an instant 'Pause auto-approve' (Home) and an automatic rollback already in the pipeline. Recommend: trial of 5 green deploys under the delegate first, then the owner turns it on. Needs a PRD amendment (local-git-ci FR41) and the owner's yes.
4. BYPASS needs the owner's server code at every start of a Bypass chat (reauth). Today the supervisor holds the code in a process environment. FIX: T-104's time-boxed LEASE granted once with the code (max 24 h, revocable, audited). After it lands: remove the code from every process environment and ROTATE the weak sign-in code 00000000 (open item), and never let a script keep it.
5. TOOL APPROVALS that remain in Bypass (Claude Code protects .git, .claude): a chat that edits those waits for a person. FIX: Keep going gets an allow-list of paths whose approval it grants itself (for example .claude/commands/** and .claude/agents/**; NEVER .claude/settings*.json, hooks, .git/config or hooks), everything else is logged and raises 'Needs you'; agents are told to avoid the protected paths (ticket the need instead).
6. QUOTA: nine Claudes, two exhausted and two near today. When none has more than the threshold left, work waits (T-105 R3). To never stop: an Account Pool of API keys as the last destination (automove.allowApiKey, off today) with a spend cap per day. Costs money: OWNER DECIDES the cap (or 'wait only'). Until then: wait and resume.
7. SECRETS: a new secret for a pool (a Cloudflare token, a key) is a person's step (secrets pools cannot be created over MCP). FIX for the common case: a documented one-time 'secrets staging' flow the coordinator runs (as done for konfersi-stg); anything new goes as one line on T-93 (prod) or a comment on T-94 (stg), never a blocking ticket.
8. PRODUCTION (T-93) and UAT (T-103) and the GitHub mirror token replacement stay human by design: they never block stg or ClaudePilot work.
9. REAL-DEVICE CHECKS (iPhone): one ticket 'Device checks' collects the list (T-1, T-2, T-3, T-5, T-24, T-25, T-28, T-32, T-34, T-42, T-99 and the new UI tickets), the owner ticks them when convenient; nothing waits for it.
