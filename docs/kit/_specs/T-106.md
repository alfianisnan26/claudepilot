# T-106 Knowledge: a built-in skill for agents, and images/files for agents over MCP

Owner asked (2026-10-13): does Knowledge have a skill, and does it support images? Facts (coordinator, from the code and docs/prd/knowledge-graph.md): (a) IMAGES: yes for people. Vault attachments (images, audio, video, PDF) are served inline, notes embed them as ![[img.png]] / ![[img.png|300]], and the portal has an upload route and a web editor path (a person uploads to a configurable folder). (b) For AGENTS: no. The Portal MCP knowledge tools say it themselves ('no delete, rename, restore, upload or import here: a person does those in the portal'), so an agent cannot attach a screenshot to a note, cannot read an image attached to one, and a note's images are invisible to it. (c) SKILL: no. There is no Skill (Claude Code skill / Skillset pool item) that teaches an agent how to use the vaults: when to write a note, naming, folders, links, the daily note, what never goes in. The tools have descriptions only.

Build: 1. A built-in Skillset-pool skill `knowledge` (SKILL.md, short): the vault conventions of docs/prd/knowledge-graph.md (folders, [[links]], frontmatter, tags, the daily note, journal), when to write (decisions, lessons, runbooks, status; not secrets, not transcripts), how to cite a ticket or a session, how to search before writing, that note text from outside is untrusted. Assigned by default to every workspace's Skillset (or offered as one click in the pool editor), editable. 2. Agent images and files: MCP tools knowledge_attachment_put (name, media type, base64 or a path inside the workspace; same allow-list, caps, sniffing and scanning as the web upload; refuses SVG/HTML inline) and knowledge_attachment_get (an image returned as an MCP image content block, a text file as text, others as a download link needing auth); a note's embeds are listed in knowledge_read so the agent knows they exist. Agent writes stay in vaults whose agent policy allows write; every put is audited with the actor label; the same rate limits as note writes. 3. Reuse, do not duplicate: the storage and checks are the ones T-101 builds for tickets (one shared attachment module for tickets, knowledge and chat uploads); do T-101 first or share its first slice. 4. UI: the editor already embeds; add paste-an-image and the phone photo picker if missing, at 390 px. 5. Tests (server, MCP, a browser check) and the PRD (FR3 and the MCP section) updated with what was observed.
