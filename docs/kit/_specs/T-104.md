# T-104 Keep going: the portal keeps an autonomous chat alive (replaces supervisor.mjs)

Owner, 2026-10-13: the supervisor (docs/dev-sessions/supervisor.mjs, a separate Node script that runs inside the dev pod with the owner's sign-in code in its environment) keeps the autonomous chats going; make it a real PILOT feature, controlled from the portal, fully implemented, and delete the script when it lands.

What it does today (the spec to keep): a chat that is idle for a few minutes is told to continue (nudge); an interrupted one is woken; an ended one is started again in its folder with a continuation prompt (caps per day, fewer after integrity endings; a chat a person closed stays closed); a question (AskUserQuestion, an elicitation) is answered with 'decide yourself' because nobody is there; a tool approval is NEVER answered, only logged; a folder whose project settings changed to permission rules only is trusted again; it picks the Claude with the most room; it never approves a deploy. Two tracks today: the ClaudePilot orchestrator and the Konfersi chat.

Why it must be a feature: it dies with the pod (a restart or a deploy leaves every autonomous chat unwatched until a person restarts it, which just happened), it needs the owner's code in a process environment, it knows two hard-coded chats, nothing shows the owner what it did, and it has no kill switch in the UI. It is NOT Claude Code's /loop or ScheduleWakeup: those are in-session timers that die with the process and know nothing about restarts, moves, quotas or Bypass. This is the portal keeping a chat alive from outside.

Build: 1. A per-chat policy 'Keep going' (on/off in the chat's menu and in New session; a default for sessions started from a ticket, a trigger or an agent token; an admin MCP tool session_keepgoing_set). Fields: nudge after N idle minutes (default 4), the continuation prompt (default text, editable, with {ticket}/{status} placeholders), a done condition (the chat calls session_done, or its ticket closes, or a marker line in a file the policy names) after which it leaves the chat alone, caps (starts and nudges per 24 h), what to do on a limit error (auto move, T-29, runs first; Keep going waits for it). 2. A server loop in the portal (the triggers/autotransfer machinery, not a script), restart-safe: its state in SQLite, one decision per chat per round, jittered, bounded. 3. BYPASS: today the supervisor re-enters Bypass with the owner's code. The portal must not weaken the Bypass gates: Keep going may re-enter Bypass only under a time-boxed LEASE the owner grants once, with the server code, for that chat ('keep this chat in Bypass across restarts until <date and time>', maximum 24 h, shown on the chat, revocable, audited, ending at once when the policy turns Bypass off); without a lease a restarted chat comes back in the default mode and Keep going says so instead of pretending. 4. The chat shows a 'Keep going' chip with today's counts (nudges, wakes, restarts) and the last action; Session info lists the actions with times; every action is an audit row with the reason; a global kill switch in Settings and on the Home page ('Pause all'), and a per-day cap in settings. 5. Questions: answered 'decide yourself' only for chats with Keep going on; a tool approval is never answered (it raises the 'Needs you' state, T-100). 6. Migrate the two tracks (orchestrator, Konfersi) to policies, with their kickoff texts as the policy prompts; delete supervisor.mjs, its notes in docs/dev-sessions/README.md and the pod process; the status-file convention stays as the done marker. 7. Authz through the seam (operate on the session); no secret in a log; a chat from outside (issue text, web page) never sets a policy; tests: the loop with a fake clock (nudge, wake, restart, caps, integrity ending, a closed chat, the lease expiring, the kill switch, a portal restart in the middle), the Bypass lease rules (refuse without the code, expiry), the UI chip at 390 px; PRD in chat-sessions.md.

Priority high, wave 2, rank 05b (right after T-100): autonomy is the point of this product and today it depends on one process in a pod.
