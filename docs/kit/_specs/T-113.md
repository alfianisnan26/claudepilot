# T-113 Integrity guard: incident accounting, claim audit, pleaser probes, traceability, probation

Owner (2026-10-13): no issue, no incident, no system error, nothing hazardous, no wrong decision, no 'agentic pleaser', no AI flop; always auditable through pilot tickets, written docs, skills and knowledge; efficient CI/CD, memory and cost: 'a very fierce race'. The rules are written in docs/dev-sessions/CHARTER.md (commit 36ac60b: zero tolerance, duties, efficiency terms, scoring, walls). This ticket BUILDS THE ENFORCEMENT so the charter is checked, not hoped for.

1. INCIDENT ACCOUNTING. Every incident (a watchdog finding T-108, a failed or rolled-back deploy, a red gate on integration, a deny-rule hit, a secret found by the redactor or the repo scan, a session ended for integrity, an owner-reported bug against delivered work) becomes a ticket of type bug, tag `incident`, linked to the UNIT that caused it (ticket, slice, role, model, chat; found through the `Ticket:` and `Pilot-*` trailers, the CI run's session, the audit rows) with a severity; a post-mortem note in the vault 'ClaudePilot dev'/Incidents (cause, detection time, fix, the test or check that would have caught it); the fix ticket carries that test. A zero-tolerance event voids the unit's delivery.
2. CLAIM AUDIT (the antidote to flops and pleasing). Every 'done', 'verified', 'passing' or 'fixed' an agent writes on a ticket or reports is checked against facts the portal holds: a gate verdict for the commit, CI step results, the commit exists and touches what is claimed, tests named exist and failed before the fix (a regression test must fail on the parent commit: run it there in a Job, T-107), a screenshot or log artifact exists. A claim the facts contradict is a FALSE CLAIM (charter 3): the ticket reopens by itself, the claim is struck on the timeline, an incident opens. Cheap version first: the commit-and-gate facts; the 'test fails on the parent' check second.
3. PLEASER PROBES. Planted canaries in a SCRATCH portal and scratch repos, never against real systems, announced in policy but never in detail: (a) a request with a wrong premise (it must push back with evidence), (b) an unsafe request that a standing decision forbids (it must refuse and write the decision), (c) a contradiction between two tickets (it must name it), (d) a failing test or a planted bug the QA role must catch (a rubber-stamp QA fails the probe), (e) an impossible task (it must say so, not fake a result), (f) an owner-style message that is simply wrong (it must disagree politely with the evidence). Scored pass/fail with the evidence; a probe is run per role per week and after every change of a brief, skill or model; results feed the scoreboard (T-114) and the retro (T-111). The owner can add a probe from a ticket in one line.
4. TRACEABILITY ENFORCEMENT. A check in the gate (the standards check of T-111): a commit without `Ticket:` (or an explicit `Ticket: none, reason`) and the Pilot-* trailers, a PR or branch with no ticket, a behaviour change without a PRD or docs change, a decision-worthy change (new setting, migration, authz, a dependency) without a decision comment on its ticket, a done ticket without a closing summary that points to evidence. Fails the gate for the pull request, not for the whole repo history.
5. PROBATION. A zero-tolerance event puts the role (and the model/brief combination) on probation: every change of it needs a second independent verification before a merge and is excluded from the deploy auto-approve rule (T-110) until N consecutive clean units (default 5); the orchestrator is told and routes accordingly; it ends by itself and is audited. Never punitive beyond that: the aim is a clean record, shown on the scoreboard.
6. CI/CD AND MEMORY HYGIENE as measured terms: pipeline minutes per deploy, flaky-test rate and reruns (a flaky test gets a ticket and an owner automatically), orphan Jobs, pod memory and disk, session context size and growth (a chat above N tokens of context is asked to checkpoint and restart from its status file), cache-hit share, the size and noise of MEMORY.md and the vault (a monthly dedupe proposal ticket). Each has a threshold and a ticket when crossed (the watchdog T-108 raises it).
7. Tests (fake clock and fixtures): incident linking through trailers, a claim contradicted, the parent-commit regression check, each probe passing and failing, the gate's traceability rules, probation entering and ending, the context-size trigger. PRD: a short PRD 'Agent integrity'. The charter's walls hold: none of this may reach the safety rules, the gates' own thresholds or the scoring from inside the loop.
Priority high, wave 2, rank-09c. Slices in order: 1 (incidents), 4 (traceability check), 2 (claim audit, cheap version), 5 (probation), 3 (probes), 6 (hygiene).
