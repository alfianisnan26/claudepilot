## 1. Principles (binding)

P1. NUMBERS ARE NEVER INVENTED. Every derived figure travels with its basis: `measured` (a stored value: tokens, the cost Claude Code reported, a percent the probe read), `estimate` (computed: rates, projections, plan "cost" which is API-equivalent and not a bill), or `unavailable` plus a short `reason` code (`no_samples`, `single_sample`, `period_reset`, `signed_out`, `no_limits`, `not_recorded`, ...). The UI labels estimates ("est." with an InfoTip that states the formula in one line) and shows "-" with the reason in an InfoTip for unavailable data. Server tests cover each basis and the edge cases (no samples, one sample, a reset inside the lookback, clock skew, zero rate, a signed-out Claude, a Claude with no limits).
P2. EXTEND, DO NOT REBUILD: apps/server/src/claudeusage/** (service, store, derive, routes, portalTools; tables claude_usage_samples and claude_usage_latest; retention: every sample 2 days, hourly to 30 days), chat/usage.ts (usageReport over chat_usage, one row per finished request with tokens, cache tokens, cost_usd, requests, agents, duration), contracts claudeusage.ts (Headroom, headroomFrom, USAGE_THRESHOLDS) and chat.ts (ChatUsageReport), the web usage page (UsagePage.tsx RequestsTab, usage/claude/{ClaudesTab,ClaudeRow,Meter,Spark,Headroom,AlertWatcher,useClaudeUsage}), the live topic `claudeusage`, the Portal MCP tool registry, the settings store (defineSetting), A2's caps (chat/caps.ts spend limit).
P3. ONE COLOUR PER CLAUDE AND PER MODEL, EVERYWHERE: the server assigns each Claude and each model a stable palette slot on first sight and keeps it (a small table; reused for ever), so every page, device, legend, widget and the Move dialog agree. Palette: colour-blind safe (an Okabe-Ito based set, checked against deuteranopia, protanopia and tritanopia simulations), at most 8 slots plus a neutral grey for "Others", and a non-colour cue (legend order, direct labels or a pattern) so colour is never the only signal.
P4. Formulas are written down in the PRD and in the InfoTip, never hidden. Sensible starting points (the owner of the area may improve them and must document the choice): spend rate = the trailing 15 minutes of chat_usage and the average since the first request today (tokens = input + output + cache writes, cache reads shown separately); quota speed per window = percentage points per hour from the claude_usage_samples of the CURRENT period only (same resets_at), least squares over at least 3 samples else first-last over 2, unavailable below 2; pace: projected % at reset = used% + speed x time-to-reset (can exceed 100), ETA to 100% = now + (100 - used%) / speed, status under or over quota from the ETA against the reset, and "ahead of even pace" = used% against the share of the window elapsed; cache hit rate = cache reads / (cache reads + uncached input + cache writes), stated in the InfoTip.
P5. Seeded, hand-checked verification: tests and browser checks use fixtures whose expected values are computed by hand and written in the test ("10% at t0, 20% at t0+1h, resets in 3h of a 5h window: speed 10 points/h, projected 50% at reset, ETA after reset: under quota"). No test asserts a number only because the code produced it.
P6. Phone first: compact forms are icon + number + dot; full forms are bottom sheets on a phone. Check 390 px and 1280 px, light and dark, keyboard and touch (tooltips and sheets reachable by both).
