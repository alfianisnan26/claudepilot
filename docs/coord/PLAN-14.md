## 2. Principles
X1. OFF BY DEFAULT, THREE GATES: a setting (default off; in production ALSO an explicit environment flag), admin only (the authorization seam), and a fresh re-auth for each window of use; every access is audited (who, which view, which filter, never the content). Disabling it stops capture and frees the buffers at once.
X2. REDACT AT CAPTURE, NEVER AT DISPLAY: what is stored in a buffer is already redacted (known patterns, known secret values, tokens of every prefix, cookies, Authorization and Set-Cookie headers, query-string secrets, environment values); sealed DB columns are never selected; request and response BODIES are not captured by default (metadata only); an opt-in "bodies" capture is per channel, clipped and redacted. A canary-secret test proves nothing planted reaches any buffer, view, log line, export or diagnostics bundle.
X3. BOUNDED EVERYTHING: fixed-size ring buffers per channel with byte and count caps, a TTL, sampling rates, a global kill switch; the overhead of capture is measured and stated (with the method); abuse (huge bodies, event floods, many tabs tailing) cannot grow memory beyond the caps.
X4. READ-ONLY: dev tools change nothing except their own capture switches and buffers (clear). The DB inspector shows sizes, WAL, migrations, normalised slow queries (parameters stripped) with EXPLAIN of those known normalised statements only, and locks; NO arbitrary SQL, NO raw rows.
X5. CORRELATION: a server-generated request id (never accepted from the client), carried with AsyncLocalStorage into runtime exec calls, controller events, slow-query entries and the live tail, so ONE request can be followed from the API to the workspace command; ids appear in a response header.
X6. HONEST NUMBERS: p50/p95 come from the sampled window with its sample count shown; estimates are labelled; unavailable data says so.
X7. ABUSE IS TESTED: secrets in logs and responses (headers, bodies, cookies, query strings, tokens, sealed values, env values), access without rights (not admin, no re-auth, expired re-auth, feature off, production without the flag), buffer bloat, log injection (CRLF, ANSI escapes, huge lines), XSS in the viewer (render as plain text), a tail that never closes.
X8. EXTEND, DO NOT REBUILD; NO COLLISIONS: reuse redact.ts, the live mechanism, the audit tables, the settings store, /healthz, the Monitoring PRD, ErrorBoundary; hooks are thin wrappers or one-line registrations added after the owning agent has reported done; text diet; the UI QA bar.
X9. MULTI-USER LIGHT TOUCH: admin-only through `can` when it lands; every audit entry carries an actor id ('u_owner' for now).
