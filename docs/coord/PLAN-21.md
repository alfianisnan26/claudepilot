## 0. The owner's ask (2026-10-12, translated; it is standard A9 in COORD/QA-STANDARDS.md)
"Strengthen the UI/UX standard for spacing and dynamic data. Check the patterns used for legends, tags, chips, user text, live lists and skeletons in ALL features first; EXTEND the existing components, do not rebuild, do not collide with work in flight. The problem: dynamic data (legends, tags, chips, user-written text) grows or shrinks in narrow areas, so rows wrap, long text disturbs other layout, and the layout shifts when data changes.
- ONE shared dynamic-list component (legend/tag/chip): a maximum count with a '+N' chip and a popover, or one row with fade/scroll; a STABLE row height.
- ONE shared dynamic-text component: ellipsis or clamp with the full text in a keyboard-accessible tooltip/InfoTip; overflow-wrap for values without spaces; a length limit at input.
- Flex/grid rules: min-width: 0 on text-bearing children, min/max widths, tabular numbers. Reserve space for dynamic content (a minimum height, skeletons of the same size, aspect-ratio). A live list does not shift what is already visible.
- Spacing only from the token scale; add/remove animation only transform/opacity.
- AUDIT all screens, replace ad hoc patterns by the shared components, record findings in docs/qa/qa-report.md with severity, owner and screenshot.
TESTING: extreme data modes (0, 1, many, hundreds of items; text of 1 and 200 characters, without spaces, emoji, RTL, huge numbers); automatic checks in a REAL browser (no horizontal scroll, no truncated text without a tooltip, no overlap, a neighbour-shift test when data is added/removed, CLS when data changes); sizes 390, phone landscape, 768, 1024, 1280, 1920, light and dark; visual regression with extreme data; no flaky tests (3 runs).
Rules: multiple agents; short UI (titles of 1-2 words, InfoTip); update the PRD and the QA standard; browser verification."

## 2. Principles
UR1. FEW, SMALL, ACCESSIBLE COMPONENTS: `ChipList` (bounded, "+N" with a keyboard-accessible popover, or a single row with fade/scroll, stable row height; optional leading swatch for legends; toggleable items for legends), `ClampText` (single-line ellipsis or N-line clamp; the full text in a keyboard-accessible tooltip ONLY when truncated; `overflow-wrap:anywhere` option for unbroken values; copy-able), `LiveList` helpers (insert at the edge or anchor the scroll so visible rows never shift; no jump under the pointer; announces additions politely), `Skeleton`-sizing helpers (same-size placeholders, aspect-ratio boxes), a tabular-number helper (compact formatting for huge values), and the layout rules documented as a short CSS recipe (min-width:0, min/max widths). Built from the kit's primitives where possible; no new dependency; tokens only.
UR2. MEASURE, DO NOT GUESS: the automatic checks run in a real browser (CDP): no horizontal scroll, no truncated text without a tooltip (compute scrollWidth > clientWidth and require a tooltip), no overlap (bounding-box intersections of siblings), a NEIGHBOUR-SHIFT test (record bounding boxes of the unchanged neighbours, add/remove data, compare: any shift beyond 0.5 px fails), CLS measured by the Layout Instability API during data changes, hit areas >= 44 px; all repeatable and deterministic with fixtures.
UR3. A UI LAB, DEV ONLY: a route (for example /admin/ui-lab) that renders every shared component with the extreme-data fixtures (0, 1, many, hundreds; 1 and 200 characters, no spaces, emoji, RTL, huge numbers; narrow and wide containers; live add/remove) so the checks and the visual regression have a stable target; excluded from the production bundle (dynamic import behind a dev flag; test that the production build does not contain it) and, if enabled elsewhere, behind the dev tools gate (PLAN-14).
UR4. ADOPTION WITHOUT COLLISIONS: UR builds the components and the lab as NEW files and announces them; owners adopt in their own files; the screen-by-screen MIGRATION (US) happens per feature when its owner is done (or in the quiet window), through small surgical edits, each re-verified by the lab checks and screenshots; every finding goes to docs/qa/qa-report.md.
UR5. NUMBERS AND CLAIMS FROM MEASUREMENT: sizes before/after, shifts and CLS in px/units with the method; the audit table lists each screen: ad hoc pattern found, replaced by what, residual risk.
UR6. COPY AND LAYOUT STAY SHORT: titles 1-2 words, InfoTip; the components add no visible text of their own except "+N" and the accessible names.
