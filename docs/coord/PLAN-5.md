## 2. Principles (binding for the whole track)

R1. ONE USER: there is one shared admin sign-in. No roles, no multi-user, no SSO. Per-device state (a push subscription, quiet hours, a widget order) is per device.
R2. NO COLLISIONS: a phase-1 implementer does not edit a file that a running agent owns. Take events from existing seams (emitters, live topics, stores) through adapters in your own module; where no seam exists, add a one-line surgical hook AFTER the owning agent has reported done (the coordinator tells you) and list every hook in your report.
R3. SECURITY FIRST: no secret in a log, a response or a transcript (webhook URLs, push endpoints and keys, signing secrets are secrets: sealed at rest, redacted everywhere); every action taken from a notification is authenticated (single-use, short-lived, request-bound, device-bound tokens or the session; verified in constant time; replay and forgery tests); inbound webhooks verify signatures (Gitea, GitHub, GitLab schemes) and size and rate limits; outbound channels go through the SSRF guard; payload text from an issue, PR or comment is UNTRUSTED input to an agent (prompt injection): triggers start sessions with the least privilege and require approvals by default; abuse tests are part of done.
R4. NUMBERS AND CLAIMS ARE NEVER INVENTED: every figure shown has a source or says it is unavailable; every PRD claim says how it was checked (verified here, documented, or unverified with a manual checklist). Real devices (iOS Safari Home Screen push, screen readers) cannot be tested here: write the manual checklist, do not claim a pass.
R5. EXTEND, DO NOT REBUILD: reuse the live mechanism, the settings store (defineSetting), the Portal MCP tool registry, the ticket-started session path, the CI events, the Move flow, the audit and redaction code.
R6. TEXT DIET, phone first, InfoTip, 390 and 1280 px, light and dark, keyboard and touch.
R7. Every automatic action (a trigger starting a session, an auto transfer, an emergency stop) leaves an audit entry and a visible trail, and has a limit (cost, parallelism, a daily cap) that is checked BEFORE acting.
