## 2. Principles (binding)
M1. DEFAULT DENY, ONE LAYER: a single authorization function `can(actor, verb, object)` (verbs view, operate, manage; actor = a user via session, an MCP token bound to an owner, a job acting for an owner, or the system) is the ONLY place rights are decided; routes, sockets, tokens and jobs call it; there is a resolver per object type so no handler reads an object without it. A test enumerates the route table and fails for a route with no authorization declaration.
M2. TOKENS NEVER EXCEED THEIR OWNER: an agent or admin token is bound to its creator, carries no more rights than the creator has at USE time (not at mint time), and dies when the user is disabled or loses the right.
M3. SECRETS AND SHARING: a share never carries secrets unless the person ticks it, with the warning; the consent screen lists everything that comes along; revoking a share removes access at once (sockets and running sessions included) and says what it cannot undo (values already read).
M4. AUTH HARDENING: argon2id or scrypt with stored parameters, constant-time comparison, per-username AND per-IP attempt limits with lockout, uniform responses (no username enumeration), safe cookie attributes, every session revoked on a password change, CSRF and Origin checks stay, the one-time setup token expires and is single use and never logged in full, open registration needs approval, invitations are single-use, expiring and rate-limited.
M5. NO SILENT OWNER LOSS: existing data migrates to the first user; a team always keeps an owner; the last platform admin cannot be removed or disabled; every state change is audited with the actor.
M6. SINGLE-USER CONTINUITY: a fresh install and an upgrade both work; the dev/test seed keeps the scratch-portal recipe and QA scripts alive and is impossible to enable in production (explicit, noisy, tested).
M7. ABUSE IS TESTED ACROSS USERS: for every object type and every route, socket message, MCP tool and job: user B cannot see, list, count, search, subscribe to, export, or operate user A's object; IDs are unguessable but never relied on; errors do not leak existence.
M8. NO COLLISIONS: the retrofit touches nearly every route file, so IMPLEMENTATION is scheduled in windows when the other tracks are quiescent (the coordinator decides); until then agents in flight follow the light-touch rules the coordinator broadcast (per-user keys with a constant default owner, owner and created_by columns on new tables, audit actors, resolvers instead of inline lookups).
