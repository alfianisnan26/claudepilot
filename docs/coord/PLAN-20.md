## 2. Principles
MX1. COVERAGE MATRIX FIRST: a table platform feature x tool (exists / gap), with the scope and the actor types (agent session token, admin token) allowed; gaps filled by priority; naming scheme `<area>_<verb>`; the full `mcp__<server>__<tool>` name within Claude Code's limit (tested).
MX2. ONE CONTRACT, ENFORCED BY A TEST: every registered tool has a JSON schema, lists have cursor pagination with a max, errors are structured (code, message, retryable, details), outputs have a size cap with a truncation marker and a `next` cursor, writes accept an idempotency key, ordering is deterministic, hints (read-only / destructive / idempotent) are declared; a test walks the registry and fails a non-conforming tool.
MX3. ONE AUTHORIZATION LAYER: tools go through the authz seam (`declarePolicies`, `requireCan`); a session token's rights are the MINIMUM of its scope and its owner's rights AT USE TIME; revoked when the session ends or the user is disabled; risky admin acts need the two-step confirmation; per-tool rate limits and audit (actor, tool, outcome, sizes, never secret values or full arguments that may hold them).
MX4. UNTRUSTED TEXT AND TOOL POISONING: everything that originated in a workspace, an agent, a ticket, a webhook or an upstream MCP server is wrapped and marked untrusted in results; control characters and bidi tricks are stripped; descriptions and results never carry instructions the portal acts on; for upstream servers (gateway) the tool list and DESCRIPTIONS are snapshotted and hashed, a change (rug pull) is flagged and the changed tools are held until a person approves; tests with injected instructions in results and descriptions.
MX5. RESILIENCE: HTTP MCP reconnect and timeout behaviour of the real CLI, `tools/list_changed`, session expiry handling, the list-change detection, canary checks with the real CLI and provider stand-ins.
MX6. THE ADMIN MCP FOR EXTERNAL CLIENTS: token management UI (create with scope, expiry, read-only vs operate, last used, revoke; per user; tokens shown once; hashed at rest); two-step confirmation for risky acts; the OAUTH DECISION written down with reasons: (A) the portal as an OAuth 2.1 authorization server (DCR or CIMD, PKCE S256, a consent screen behind the portal sign-in, short-lived access tokens with refresh, scopes mapped to read/operate, a redirect-URI allowlist (claude.ai/claude.com callbacks and loopback), revocation, rate limits) or (B) short-lived tokens issued in the UI for clients that accept a header (VS Code, CLI) with claude.ai unsupported until A: recommend with the security analysis; the owner decides; docs and connection examples for claude.ai, VS Code and the CLI.
MX7. THE POOL GATEWAY: the workspace connects to ONE portal gateway endpoint with its session token; the gateway connects to the pool's upstream servers (remote HTTP/SSE; the stdio question: where would they run and how are they sandboxed), INJECTS secrets server-side (the workspace never sees a value), applies per-tool allow/deny rules and argument validation, logs usage without content, snapshots tools (MX4), health-checks upstreams, and ENFORCES pool-only (the workspace's only MCP server is the gateway; the lockdown stays as defence in depth); SSRF guard on upstream URLs; confused-deputy protection (a secret is only ever sent to the upstream it was bound to); backpressure and timeouts; behaviour when an upstream is down; the OAuth-upstream question flagged for the owner (the gateway holding upstream OAuth tokens reverses D1 for gateway sets).
MX8. ABUSE TESTS WRITTEN OUT: user B's token against user A's objects on every tool; a leaked or revoked token; an expired session; tool poisoning (a changed description or schema); prompt injection in results; confused deputy; SSRF through upstream URLs; output flooding; rate-limit evasion; token in logs (canary test).
MX9. EXTEND, DO NOT REBUILD; NO COLLISIONS: new tools register through the registry (other tracks are adding tools: no edits to their tool files, only the shared conformance test and a registry hook); the gateway and admin-token UI in new files; surgical hooks after owners are done; storage declaration; QA UI bar.
