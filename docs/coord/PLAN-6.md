## 2. Principles (binding)

E1. SECURITY FIRST. Screenshots can hold secrets: blur tools, a visible warning before anything leaves the capture screen, and no automatic send. Page text, the DOM, console output, request URLs and anything quoted from code or documents are UNTRUSTED input to an agent (prompt injection): forwarded quotes are marked as untrusted data in the card and in the tool results, and are never interpreted as instructions by the portal. Annotation text is rendered as plain text (no HTML, no markdown HTML), sanitised and clipped. The viewer reads files only through the existing server file paths and rules (deny rules, redaction); it adds no new route to a secret, and it never reveals the content of a denied or redacted file (it says so). Size limits and retention for every stored thing; a hash (sha256) and a capture time stored with every capture; HAR and trace files are redacted for credentials (headers, cookies, tokens, query secrets) before storage and the redaction is stated.
E2. EXTEND, DO NOT REBUILD: the artifact and blob store (one storage, many references: content-addressed blobs with links, never copies), the composer attachment path, portal chat cards, the ticket and knowledge stores, the Portal MCP registry and its session scoping, the existing viewer for phones.
E3. NO COLLISIONS: do not edit files owned by a running agent; take what you need from existing seams or add surgical one-line hooks after the owner reports done (the coordinator says when); list every hook in your report.
E4. ANCHORS NEVER MOVE SILENTLY: an annotation anchors to a version (a file hash, a commit, a document revision) and a quoted text with enough surrounding context to re-find it; when the version changes, re-anchor only on an exact or clearly unique match and otherwise mark it "outdated" with the version it was made on; never relocate it to a different place. This is tested.
E5. NUMBERS AND CLAIMS ARE NEVER INVENTED; mark what is unavailable; real devices (iOS Safari capture, Monaco on touch, screen readers) cannot be tested here: write the manual checklist, do not claim a pass. The desktop tier of the browser pool is only as built.
E6. TEXT DIET, phone first (the phone keeps the light viewer and a simple annotation list), InfoTip, 390 and 1280 px, light and dark, keyboard and touch.
E7. Every automatic action (a review sent to a session on its own, evidence uploaded by an agent) leaves an audit entry and a visible trail, is size-limited, and is append-only for agents.
E8. CSP and bundle: Monaco and Shiki load lazily as their own chunks, workers come from our own origin (no blob: or CDN worker unless the CSP is changed deliberately and the change is justified), and the main bundle must not grow measurably (state the before and after sizes).
