## 2. Principles
GD1. THE CHECKLIST IS DERIVED FROM REAL STATE: each step has a real check (Claude signed in and not expired; at least one workspace reachable; at least one session; the PWA installed (display-mode standalone) AND the push subscription state) and an action button that goes to the place; never a stored flag; one screen; dismissible and reopenable from Help; honest "unknown" when a state cannot be read.
GD2. TOURS: 3-5 steps per main area (Workspaces, Sessions, Usage, Pools, Tickets, Settings, ...), each step anchored to a real element, completed when the user PERFORMS the action (an event, not a click on Next), skippable at any time, resumable, repeatable from the Help menu; no modal blocking; one tour at a time.
GD3. ONE TOOLTIP COMPONENT: InfoTip is the one; extend it where it falls short (keyboard: focus opens, Esc closes, tap on touch, aria-describedby, no hover-only, placement that avoids edges and the phone keyboard); replace ad hoc long-text `title` attributes and one-off popovers by it; copy follows the text diet.
GD4. DISCOVERY TIPS AND WHAT'S NEW: a coachmark appears ONCE, triggered by REAL first use of a menu or feature (open, focus, first action), never by a timer; "What's new" once per version change from a versioned changelog data file shipped with the app (a short list, no marketing words); both recorded as seen on the server per user.
GD5. THE ENGINE ENFORCES THE RULES (not each feature): at most one tip per screen; never over the primary action, the focused input or the phone keyboard (collision checks with a fallback to an inline hint); suppressed while loading, in an error state, or while an approval is waiting (the gate signal); respects prefers-reduced-motion; non-modal; focus is never stolen; polite aria-live; Esc dismisses; dismissing records seen; tips never appear in the glance popovers/sheets or dialogs.
GD6. STATE ON THE SERVER, PER USER: `guide_seen` and tour progress; endpoints behind the authz seam (a user sees and changes only their own); "Reset tips" for the user, an admin setting that switches guidance off platform-wide; nothing sensitive stored (ids and versions only); the storage declaration in the PRD.
GD7. A CENTRAL REGISTRY: every feature registers its tips in ONE registry (id, area, trigger, since-version, anchor `data-guide="<id>"`, copy key, priority); a TEST fails when a registered tip's anchor is missing from the source, when ids collide, or when a tip has no copy; the PRD template gains a "Guidance" line (the tips the feature registers) and agents building UI from now on add their tips (a coordinator broadcast after the framework lands); existing features get their tips in a later pass.
GD8. LIGHTWEIGHT AND MEASURED: our own small components, no tour library; lazy-loaded; the bundle size before and after is measured and stated; no layout shift; animation 120-250 ms, transform/opacity only.
GD9. COPY: short, concrete, no generic AI phrases ("Seamless", "Powerful", "Let's get started!"), consistent terms across the app; one glossary line per term in the PRD.
GD10. TESTED END TO END IN A REAL BROWSER, deterministic with fake data: appears once; does not appear again after being closed; never covers an action; works by keyboard; 390 to 1920 px; reduced motion; three-run flake gate; plus unit tests for the engine's rules (one per screen, suppression, once-only, version change).
GD11. EXTEND, DO NOT REBUILD; NO COLLISIONS: the shell, nav, Settings and feature pages are edited surgically after re-reading; the Help entry and the gate signal are added through small seams; UI QA bar; text diet.
